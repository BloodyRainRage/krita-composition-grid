Composition Grid

A non-destructive composition grid that floats above the canvas: it is a widget overlay, not a paint layer. It never changes the image, never appears in exports (PNG, TIFF, print) and never blocks drawing or panning. Turning it off, moving it or deleting it has no effect on the document whatsoever.

Panel

Enable the panel from Krita's docker list (Settings ▸ Dockers ▸ Composition Grid; the internal id is composition_grid_docker). One panel per window. It holds:

  • The grid list — one row per grid of the active document, in the order you added them, reading <label> — <grid type>. Click a row to select that grid and start editing it on the canvas at once: the move/resize handles appear without pressing Edit Grid on Canvas, and every control below shows that grid. Double-click a row (or press F2) to rename its label in place; the editor holds the label alone, and an empty name keeps the old one. The eye at the left of a row shows and hides that grid only — toggling a neighbour neither changes your selection nor ends the edit session of the grid you are working on, and a hidden grid draws dimmed. Arrow keys select a grid without starting a session; a hidden grid is only selected, since there is nothing on the canvas to drag. The list keeps a fixed height and scrolls when the document has more grids than fit.
  • Grid type — one of the 12 types: Rule of Thirds, Center Cross, Quadrant Grid, Golden Ratio (Phi), Rule of Fifths, Uniform Grid, Symmetry Axes, Golden Spiral, Golden Triangles, Diagonal Method, Dynamic Symmetry, Perspective. Every type is drawn from the current grid-element bounds, so it adapts automatically when you move, resize or rotate the element.
  • Parameters — the options of the selected type (columns/rows/margin, axis counts, spiral origin, root ratio, vanishing-point position, and so on). Changing the type keeps the grid element and the style; the parameters are replaced by the new type's defaults — remembering separate parameter values per type is not part of version 1.
  • Style — color button (a color dialog), line width (0.25 px … 12 px, in screen pixels so it stays constant while zooming), opacity slider, and the dash preset: Solid, Dash, Dot, DashDot.
  • Transform — Reset Transform (back to the default element for the current document), a numeric Rotation (deg) field, and the Lock Ratio checkbox (on by default).
  • Visible checkbox and the checkable Edit Grid on Canvas button — the button mirrors the session your row click started, and pressing it again (or clicking past the markers on the canvas) ends it.
  • Add grid / Remove grid — the two buttons directly under the list. A document can hold any number of grids, so adding and removing are two separate buttons. Add grid appends a new grid (starting from the last type, parameters and style you used, placed as the centered default element) and selects it. Remove grid deletes the selected grid and selects the next one, or the previous one, or nothing; Remove grid and the editing controls are disabled while no grid is selected. Removal is not a hide: Visible means "keep this grid, do not draw it", removal means "this document no longer has it".

The panel always edits the selected grid of the active document; the other grids of the same document keep their own type, parameters, style, element and visibility. Select one in the list at the top of the panel, or use the actions below to add, remove and cycle the selected one.

Each grid has a label: a new grid gets the next free number (1, then 2, …), and two grids may share a name — the ids, not the names, identify a grid. Double-click the row (or press F2) to rename it; the label is saved with the document.

Editing the grid on the canvas

Every visible grid of the document is drawn, each with its own style, in the order you added them. The grid is passive by default: the lines are visible and every mouse event goes through to Krita. Click Edit Grid on Canvas (or run the Toggle Grid Edit Session action) to make the selected grid interactive; only its markers appear (the element frame itself is not drawn):

  • four corner markers and four edge markers resize the element, the dragged corner/edge follows the pointer while the opposite one stays put;
  • the move marker (a four-way arrow cross at the element center) drags the element — and in an edit session you can grab anywhere inside the grid to move it, not just that marker;
  • the rotation marker above the top edge rotates it around the element center (clockwise on screen is a positive angle, the same as the panel field);
  • the vanishing-point marker exists only for the Perspective type and drags its vanishing point.

While dragging a corner, holding Shift temporarily inverts the current Lock Ratio state. The handles and the mouse belong to the selected grid only: a click that lands on another grid, or anywhere else, ends the edit session and continues into Krita as usual (a click inside the selected grid is a move-drag, not a miss). Click the button again (or run the action) to leave the session.

Actions

Six entries are added to Tools ▸ Scripts:

  • Add Composition Grid — append a new grid to the document and select it. This is the only way a grid appears: a new or freshly opened document has none.
  • Toggle Composition Grid — show or hide the selected grid. With no grid in the document it does nothing (it never creates one).
  • Remove Composition Grid — delete the selected grid; the selection moves to the next grid, else to the previous one, else there is no selection.
  • Toggle Grid Edit Session — enter or leave the interactive session for the selected grid.
  • Reset Grid Transform — return the selected element to the default position and size for the current document.
  • Cycle Grid Type — switch the selected grid to the next type in the panel's order (wrapping around).

No keyboard shortcuts are assigned by default; assign them in Settings ▸ Configure Krita ▸ Keyboard Shortcuts.

Per-document state and saved settings

Each open document keeps its own list of grids plus the one grid it has selected. A new document — and a document opened from a file that stores no grid state — has no grid at all: nothing is drawn and the mouse stays with Krita until you add one. When a grid is added, its element is a square centered on the page, 80 % of the shorter document side, unrotated.

The grids of a document are saved inside that document. Once you change one — add, remove, rename, type, parameters, style, element, visibility or the selection — the whole list is stored in the .kra file itself (as file metadata, never as a layer or a pixel), so reopening the file puts every grid back in the same order with the same selection, and the file carries them to another computer. Opening a file never changes it: the state is only written when you actually change a grid, so merely looking at a file does not mark it modified. Files saved by the previous version are migrated on open: its single grid comes back labelled 1, and a file whose grid had been removed opens without one.

In addition, the type, parameters and style of the grid you last edited are remembered in Krita's configuration (group composition_grid) and are used for one thing only: seeding a new grid when you press Add grid. They never restore a document's grids. The element position, size and rotation are not taken from there — a new grid always gets the centered default element of its own document.

Limitations

  • No reordering of the grid list yet: the rows follow the order the grids were added (or restored from the file) in, and there are no per-grid parameter presets to pick from.
  • Deferred: no user presets, no snapping to canvas content and no separate parameter memory per grid type.
  • Zoom, pan, view rotation and mirroring are tracked through Krita's canvas signals; after a display-config or level-of-detail change (which rebuilds the canvas widget) the overlay re-attaches when the active view changes.
  • In detached/floating-canvas arrangements Krita may not expose a usable canvas widget to plugins; the grid then simply stays hidden instead of misbehaving.
  • Line width and dash patterns are measured in screen pixels, so they do not scale with zoom by design.
